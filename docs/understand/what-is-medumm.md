# MedUMM 是什么？

## 一句话解释

MedUMM 把不同医学多模态模型、医学数据集、评测协议和后训练方法放在一套稳定接口后面，让研究者能用相同的配置、运行流程和证据标准做实验。

## 它解决的不是“再做一个模型”

医学多模态研究常见的问题是：每个模型都有自己的安装、输入格式、推理脚本和输出；每个数据集又有不同字段、许可和指标；最后很难知道两个结果是否真的可比较。

MedUMM 把问题拆成四类可替换组件：

| 组件 | 负责什么 | 不负责什么 |
|---|---|---|
| Model adapter | 加载模型、声明能力、执行批量任务 | 不定义整个基准协议 |
| Dataset adapter | 规范化样本、记录来源与指纹 | 不直接决定模型实现 |
| Benchmark adapter | 构造请求、解析输出、评分和汇总 | 不隐藏缺失标注 |
| Post trainer | 执行一种训练路线并返回标准结果 | 不把 smoke test 称为论文复现 |

## “统一”是什么意思

统一的是接口和证据，不是强迫所有模型使用同一个内部实现。

- 能共享 Transformers 接口的模型可以共享执行器。
- 依赖冲突或拥有官方运行时的模型通过隔离 bridge 接入。
- 医学任务共享请求和结果对象，但保留各自的任务语义和指标。
- CLI 与 Python API 使用同一编排逻辑。

## 它与 TorchUMM 的关系

MedUMM 借鉴统一多模态工具包的四层组织方式和可插拔思想，但目标是医学领域：强调医学任务语义、数据治理、临床相关指标、验证等级和可审计证据。项目不会把自然图像分类的单一 top-1 范式直接套到报告、定位、测量、医学推理或纵向记录上。

## 当前边界

MedUMM 已有大规模资源目录和多条真实运行切片，但“目录中存在”不等于“完整跑通过”。完整理解项目时，请先阅读 [验证等级](validation.md)。
