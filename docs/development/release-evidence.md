# 发布与证据规范

## 每个版本应包含

1. 版本号与精确 Git commit；
2. 功能范围和公共接口变化；
3. 单元/集成测试计数与跳过原因；
4. 服务器、调度器、节点、Python、PyTorch、CUDA、GPU；
5. 模型、数据、源码和协议 revision；
6. 成功作业 ID、退出码、样本数与指标；
7. 失败尝试、根因与修复；
8. validation level 与明确 limitations。

## 推荐的证据文件

使用 JSON 存放审查所需的紧凑事实；完整日志可以留在服务器，但路径和保留策略需要记录。证据文件应提交到代码仓库并随 tag 固定。

## 性能结果

必须同时记录硬件、模型、输入/输出长度、warm-up、请求数、并发、调度配置和缓存状态。吞吐提升只能在相同配置的 profile 间比较。

## 科学与临床表述

工程运行成功 ≠ 模型质量；小样本 wiring slice ≠ 全数据集性能；公开基准分数 ≠ 临床有效性；论文方法的 contract smoke ≠ 论文复现。
