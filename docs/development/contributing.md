# 开发与贡献规范

## 基本原则

- 保持公共接口小而稳定，模型特有参数放在其 `config` 或请求 `parameters` 中。
- 重依赖惰性导入；冲突运行时采用隔离 bridge。
- 所有外部模型、数据、源码和协议使用不可变 revision。
- 新医学数据先治理、后加载权重。
- 测试与 smoke 结果不能替代真实运行或论文复现。

## 建议开发流程

```bash
git switch -c agent/your-feature
python -m pytest
git diff --check
```

一个功能提交至少应包含：实现、最小配置、失败边界测试、文档和相称的验证证据。不要提交模型权重、受限数据、凭证或包含患者标识的信息。

## 代码审查检查点

1. 接口是否复用已有 request/result/runtime？
2. 能力声明是否与实际实现一致？
3. 不支持的组合是否尽早、明确失败？
4. 外部来源和 revision 是否可追溯？
5. 日志和清单是否泄露秘密？
6. 验证等级是否被准确表述？
